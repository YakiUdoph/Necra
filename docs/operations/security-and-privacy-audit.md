# T012 security and privacy audit

Status date: 2026-11-07. A `PASS` is limited to repository and local-test evidence; it is not a production-readiness claim.

| #   | Control                              | Status       | Evidence or remaining gap                                                                                                                                                                  |
| --- | ------------------------------------ | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Clocked keys are server-only         | PASS         | `CLOCKED_API_KEY` is parsed only by `src/server/env.ts`, which imports `server-only`; the browser receives no credential.                                                                  |
| 2   | No secrets in tracked/browser files  | PASS         | Environment files are ignored, the example is blank, tracked-source pattern review found no credential, and the production browser bundle secret-value scan is part of the release gate.   |
| 3   | Server-side authentication           | PASS         | Protected pages and API services require a verified database-backed Better Auth session.                                                                                                   |
| 4   | Tenant/project isolation             | PASS         | Services re-check active workspace/project membership and scope queries by project/workspace; denial cases have integration coverage.                                                      |
| 5   | Server-side write validation         | PASS         | Mutation routes bound request size, enforce origin checks, and parse typed schemas before transactional services.                                                                          |
| 6   | Clocked rate limiting                | PASS         | Clocked claims take ordered PostgreSQL deployment-wide and workspace advisory locks and enforce configurable 24-hour ceilings before transport.                                            |
| 7   | Concurrent credit protection         | PASS         | Database-coordinated global and per-workspace running limits work across application instances; both default to one concurrent call.                                                       |
| 8   | Budgets/failure limits               | PASS         | Global and workspace attempt budgets default to 20/24h, retries count as new calls, each run has exponential backoff and at most four attempts, and unknown outcomes enter reconciliation. |
| 9   | Safe user errors                     | PASS         | Known failures map to bounded messages/statuses; route responses do not serialize exceptions or stacks.                                                                                    |
| 10  | Logs exclude credentials/source text | PASS         | Application code does not log credentials, source bodies, or provider payloads. Hosting-platform behavior remains an operator responsibility.                                              |

| 12  | CSRF/origin protection               | PASS         | Same-origin and Fetch Metadata checks cover mutations; Better Auth CSRF/origin checks remain enabled.                                                                                      |
| 13  | Restricted production DB permissions | NOT VERIFIED | The required role split is documented, but no production database or roles exist.                                                                                                          |
| 14  | Sensitive actions auditable          | PASS         | Source, check, validated provider, review, and decision events are persisted; decisions and audit records are append-only.                                                                 |
